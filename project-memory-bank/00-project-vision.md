# 00 — Project Vision

Status: ACTIVE
Last updated: 2026-09-19 (Phase 0)
Source: Master system prompt "Engineering Intelligence OS" v1.0, sections 1–6, 99

## FACT — Product

Engineering Intelligence OS: a persistent intelligence layer that gives engineers and AI agents the context, memory, evidence, evaluation, and judgment support required to make better engineering decisions.

## FACT — Core thesis

As AI agents become increasingly capable of writing and modifying software, engineering context, memory, evidence, evaluation, verification, and judgment become increasingly important. The product is that missing layer.

```
Engineering Intelligence = Context + Memory + Evidence + Evaluation + Trust + Human Judgment
```

## FACT — Value chain the product must eventually connect

Goals → Strategy → Execution → Engineering Work → Knowledge → Memory → Decisions → Evidence → Evaluation → Artifacts → Learning → Career Growth

## FACT — Three product layers (build in order, not simultaneously)

1. Personal Engineering OS — individual engineers: goals, execution, memory, decisions, learning, interview prep, evidence, artifacts.
2. Engineering Context Platform — AI-native developers: code/project context, architectural memory, decision history, agent context compilation, evaluation, verification.
3. Engineering Intelligence Platform — teams/enterprises: shared memory, org context, agent governance, evaluation, observability, security, enterprise controls.

## FACT — First target user

Senior/Staff/Principal engineers who use AI coding tools and experience significant engineering-context overload. The creator is the first serious user (spec §87).

## FACT — North star

Verified Engineering Leverage = Meaningful Engineering Outcomes ÷ (Human Time + Cognitive Load + AI Cost + Rework).

Not a success metric: task count, AI call count, token count, note count, dashboard interactions.

## FACT — What this is NOT

Not a todo app, note app, generic chatbot, project-management tool, resume builder, interview-question database, or vanity-metrics dashboard.

## CONSTRAINT — The most important rule

Build less. Learn faster. Measure everything important. Preserve context. Prove value. Stop after each phase and wait for explicit approval.
