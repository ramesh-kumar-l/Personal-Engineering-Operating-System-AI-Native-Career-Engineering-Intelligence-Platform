# 05 — User Flows

Status: UNKNOWN — to be defined in Phase 1 (foundation flows) and Phase 2 (execution flows)
Last updated: 2026-09-19 (Phase 0)

## FACT — Flows implied by the golden use cases ([[03-product-strategy]])

1. Morning: review goals → review workload → "I have N minutes" → receive NOW/NEXT/LATER with WHY.
2. During work: describe task → receive minimum sufficient context (code via ECC + personal memory/decisions from this repo) → hand to agent.
3. Evening: capture what was done → extract Problem/Action/Decision/Impact → store as evidence → suggest artifact/interview story.
4. Weekly: review progress, detect drift, regenerate priorities.

## CONSTRAINT

Automations must be transparent and user-controlled (spec §49). Every significant UI flow goes through `/frontend-design` before implementation (spec §53).

## NEXT ACTION (Phase 1/2)

Document each flow as Problem → User Flow → Information Architecture → Interaction → states (loading, empty, error, recovery).
